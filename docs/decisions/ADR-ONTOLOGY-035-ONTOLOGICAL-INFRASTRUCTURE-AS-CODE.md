## 1. Context and Problem Statement

Scientific ontologies and knowledge graphs in CoResearcher govern the canonical taxonomy of diseases, biological programs, physical invariants, and formal claims (`docs/ONTOLOGY_CONSTITUTION.md`). 

However, in Description Logics (OWL/RDF) and scientific knowledge graphs, **semantic changes exhibit non-linear consequence expansion**:
> *"One line in an ontology, 901 new consequences. Giving `hasParent` the domain `Person` infers every individual with a parent to be a `Person`, while a plain text diff displays only the single altered line."*

In automated AI discovery pipelines, unmonitored ontology modifications present fatal hazards:
1. **Silent Epistemic Corruption**: An agent updating a domain boundary can inadvertently trigger thousands of unsound deductions, muting valid hypotheses or causing contradictory cascades.
2. **Invisible Blast Radius**: Standard git commits show text line diffs (+/- 1 line) while obscuring the true epistemic explosion of derived consequences across the graph.
3. **Lack of Transactional Safety & Rollback**: Autonomous agent swarms operating on shared knowledge graphs need atomic operations with clean reversal guarantees (`plan`, `apply`, `rollback`).
4. **Unverified Reasoner Proofs**: Large DL reasoners (or LLMs acting as ontologists) require an offline, independent formal checker to re-verify deduplication and entailment proofs.

---

## 2. Decision and Invariants

Inspired by `open-ontologies` (Lindenberg & Rovai, 2026), CoResearcher ratifies **ADR-ONTOLOGY-035**, establishing **Ontological Infrastructure-as-Code (IaC) & Epistemic Blast Radius Gates** for the CoResearcher Scientific Ontology (CSO):

### Invariant 1: Terraform-Style Epistemic Lifecycle (`plan` -> `apply` -> `rollback`)
No ontological mutation (adding an axiom, altering class subsumption, or modifying domain/range constraints) is committed directly to the canonical graph.
All mutations MUST transition through an auditable transactional lifecycle:
- **`plan(ontology_diff)`**: Computes the prospective deductive closure, counting newly inferred triples, affected downstream claims, and potential contradiction faults. Returns an `OntologyBlastRadiusReport`.
- **`apply(plan_id)`**: Atomically applies the transaction to the ontology state, snapshotting the previous state and anchoring the execution in `ScientificCommit`.
- **`rollback(transaction_id)`**: Immediately restores the pre-mutation ontology snapshot, invalidating all ephemeral deductions.

### Invariant 2: Explicit Epistemic Blast Radius Quantification
Every planned ontology mutation produces a formal blast-radius report quantifying:
$$\text{BlastRadius} = \Delta \text{DirectInferences} + \Delta \text{TransitiveConsequences} + \Delta \text{AffectedEntities}$$
Mutations with an excessive blast radius ($> 100$ unintended transitive consequences or any contradiction collapse) require mandatory human-in-the-loop escalation or secondary gate approval.

### Invariant 3: Offline Proof Re-Verification Gate (Independent Reasoner Checker)
Following the dual-verification principle (`ADR-EPISTEMIC-034`), any consequence proof generated by an ontological reasoner or agent proposal MUST be validated by an offline exact checker (evaluating acyclicity, subsumption consistency, and conservation invariants) before permanent incorporation into the ledger.

### Invariant 4: Model Context Protocol (MCP) Integration
Ontology lifecycle operations are exposed as first-class MCP tools (`cso_plan_ontology_change`, `cso_apply_ontology_change`, `cso_rollback_ontology_change`) to enable safe, programmatic collaboration among autonomous research agents.
