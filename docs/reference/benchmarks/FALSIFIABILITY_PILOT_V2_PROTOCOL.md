# Falsifiability pilot, version 2: formal hypotheses, pre-registered

Status: drafted on 2026-10-20, before any run of this version. Version 1
(`FALSIFIABILITY_PILOT_PROTOCOL.md`, results in `falsifiability/falsifiability_results.json`) stays frozen as it was run.
This document does not change it.

## 1. Why a version 2

Version 1 asked the formalizer to translate prose hypotheses into the formal format. It worked for 2 of 200 hypotheses.
The diagnostic (`diagnostic_formalization.jsonl`, 20 excluded items) showed two causes:

- 11 of 20 formalized, but the five consistency samples disagreed, so the gate excluded them. The model reads the same
  hypothesis in different ways.
- 8 of 20 wrote predicates outside the language (for example "is a real number", "for all", "implies", subscripts).
  1 of 20 returned no JSON.

The bottleneck is the translation from prose, not the falsifiability measure. Version 1's result is kept as a documented
negative finding: with this formalizer, prose hypotheses cannot be measured.

## 2. Change

The generator writes each hypothesis **directly** as a formal object, in the JSON form that the evaluator accepts
(`hypothesis_from_dict`). There is no translation step, and therefore no consistency gate.

## 3. Scope of the result

Results of version 2 apply to **formal hypotheses generated by the pinned model**. They say nothing about prose
hypotheses, which version 1 already shows cannot be measured with this formalizer. This narrower question is the price of
a measurable one, and every report of version 2 must say so.

## 4. Procedure

1. **Question bank.** The same 200 questions as version 1 (`inspiration/question_bank.json`, one per question).
2. **Generation.** Model `qwen2.5:14b-instruct-q4_K_M`, temperature 0, seed `63000 + index`. The prompt is in section 7.
   One completion per question. No retries.
3. **Validity.** The output is parsed as JSON and passed to `hypothesis_from_dict`. Outputs that fail are recorded as
   `INVALID` with the error. They stay in the denominator.
4. **Exact measure.** Unchanged from version 1: content verdict and forbidden fraction from the formal evaluator.
   **Amendment (2026-10-20, before any measure output was saved).** An object that constructs but whose predicates
   raise an evaluation error on its own declared domain (for example a domain that mixes numbers and text, compared with
   `<`) is `INVALID`, with the error recorded as the reason. The first `measure` run stopped on such an object (item 54)
   and saved nothing. The rule applies to every object alike; it is an existing category of the protocol, not a new
   threshold.
   A state space above `max_states` is `BLOCKED` and excluded, and counted.
5. **Rubric.** The judge `qwen2.5-coder:32b` receives the question and the formal object as JSON. It rates falsifiability
   from 1 to 10 with three reviews (seeds `64000 + k`), the median taken. The judge does not see the exact measure.
6. **Analysis.** Q1 and Q2 as in version 1, with the same thresholds: kappa criterion 0.40, informativeness threshold
   0.05, informative-share criterion 0.70. Q3 is not run: there are no revision pairs.

## 5. Limitations, stated in advance

- The same model writes the formal objects and the judge reads them, so the agreement is partly within one model family.
- The exact measure depends on the declared domains. Each variable's domain is written by the model, so the forbidden
  fraction measures the model's own discretisation, not the world.
- A hypothesis can be falsifiable and still uninformative (for example one that forbids a single state). Q2 is there to
  count that.

## 6. Pre-registration rule

No version 2 run starts until this file, the generator prompt and the scoring code are committed. The hashes of all three
are recorded with the first output. Thresholds do not change after any result is seen.

## 7. Generator prompt (frozen)

Write one scientific hypothesis for the research question below, as a JSON object with these keys:
`hypothesis_id` (string), `variables` (a list of objects with `name` and `domain`, where the domain is a list of at most
10 values), `assumptions` (a list of predicates), `claims` (a list of predicates, at least one).

A predicate is a string that uses only: comparisons (`==`, `!=`, `<`, `<=`, `>`, `>=`), `and`, `or`, `not`, parentheses,
arithmetic, and `in` with a literal list. Write implication as `(not A) or B`. Do not use quantifiers, subscripts,
function calls other than the listed operators, or prose inside a predicate.

Answer only with the JSON object.

Research question: {question}

## 8. Rubric prompt (frozen)

You review a scientific hypothesis, given here as a formal object. Rate its falsifiability on a scale from 1 (no
observation could refute it) to 10 (it names a precise observation that would refute it). Answer only with JSON:
{"falsifiability": <integer 1-10>}

Research question: {question}
Hypothesis (formal object): {hypothesis}
