## Metadata Mapping Verified

The normalizer maps `ScientificLedger` fields to Zenodo deposit metadata:

| Zenodo field | Source |
|---|---|
| `title` | `ledger.name` |
| `description` | `ledger.description` + `ledger.comprehension_summary` + generation note |
| `creators` | Deduplicated `ledger.contributors` with ORCID support |
| `dates` | `ledger.generated_at` as `Issued` |
| `keywords` | Deduplicated `workstreams.signals` + `scientific_unit` (max 20) |
| `related_identifiers` | Artifact DOIs + GitHub repos |
| `upload_type` | `dataset` (hardcoded) |
| `notes` | ledger_id, artifact count, workstream count, scientific_unit, unit_rationale, start_year |

## Scientific Semantics: The Unit of Knowledge

The technical achievement is a `ScientificLedger → Zenodo → DOI` path.

The strategic question is: **what is the minimal scientific unit that this ledger represents?**

Options considered:
- Project-level
- Investigation-level
- Experiment-level

Working hypothesis now encoded in `ScientificLedger.scientific_unit`:
> **One investigatable claim or question** within a project.

This is looser than a paper and tighter than a repository. It maps to:
- A workstream + its evidence + its artifact set + its contributors.
- The minimal traceable unit of scientific activity.

This semantic layer determines whether ledgers get cited or ignored.

---

## What This Means for CoResearcher

CoResearcher is no longer limited to observing scientific activity. It can now publish the **Scientific Activity Ledger** as a citable Zenodo object.

This closes the loop:

```text
Evidence (GitHub, OpenAlex, Crossref, Zenodo)
    ↓
Artifacts
    ↓
ScientificLedger
    ↓
ZenodoPublisher.deposit()
    ↓
Zenodo Deposit
    ↓
DOI (10.5281/zenodo.XXXXXX)
```

The ledger becomes a **first-class scientific object**:
- **Persistent**: DOI does not change.
- **Versioned**: Each new deposit is a new version.
- **Citable**: Agents and humans can cite the ledger in papers.
- **Reproducible**: Future runs can compare against the cited ledger snapshot.
