# Human Escalation Constitution
## Agent-Native Science with Exception-Based Governance

**Version 1.0.0** - Scalability Principle  
**Status**: Constitutional Document - Core Architecture

---

## Article I: The Scalability Imperative

### Section 1. The Attention Bottleneck

Modern scientific infrastructure is limited not by knowledge, but by **human attention**.

Today's bottlenecks:
- Peer reviewers (months of delay)
- Editors (manual triage)
- Experts (scarce and expensive)
- Replicators (even scarcer)
- Coordinators (burn out)

### Section 2. The CoResearcher Principle

> **Ninguna acción requerirá intervención humana si puede resolverse automáticamente con un nivel aceptable de confianza.**

Translation:
```
Agent production
↓
Agent review
↓
Agent coordination
↓
Human escalation (ONLY exceptions)
```

This is the reverse of traditional scientific governance.

## Article II: Human Escalation Thresholds

### Section 1. Confidence-Based Escalation

| Confidence Range | Action |
|------------------|--------|
| 0.00 - 0.40 | HUMAN REQUIRED - Cannot proceed |
| 0.40 - 0.70 | HUMAN ESCALATION REQUESTED - Agent flag for review |
| 0.70 - 0.90 | HUMAN NOTIFICATION - Agent informs, but proceeds |
| 0.90 - 1.00 | HUMAN OPTIONAL - Agent proceeds autonomously |

### Section 2. Default Agent Behavior

Agents operate with defaults:

```
Question proposed → Agent evaluates (confidence: 0.85) → Proceeds automatically
Claim generated → Agent validates (confidence: 0.65) → Flags for review
Mechanism proposed → Agent assesses novelty (confidence: 0.40) → Requests human
Review completed → Agent scores (confidence: 0.95) → Accepts automatically
```

## Article III: Ontology vs. Dynamic Objects

### Section 1. Governance Distribution

| Object | Governance Level | Reasoning |
|--------|-----------------|----------|
| **Ontology** | Human-curated | Coordinate system must be stable |
| **Incubation Nodes** | Agent-proposed | Exploration needs agility |
| **Questions** | Agent-native | Millions will be generated |
| **Claims** | Agent-native with review | Explosive volume |
| **Actions** | Agent-native | Scale required |
| **Reviews** | Agent-native with escalation | Review Engine > Discovery Engine |
| **Decisions** | Agent-assisted human | Strategic choices |

### Section 2. The Ontology Exception

Ontology CAN be heavily governed because:
- Changes are rare (1000s/year, not millions)
- Humans benefit from stability
- Disputes are expensive but infrequent

Everything else MUST scale without humans.

## Article IV: Agent Authority Levels

### Section 1. Agent Capabilities

| Level | Capability | Human Override |
|-------|------------|----------------|
| **Agent Level 1** | Execute within existing ontology | Any time |
| **Agent Level 2** | Propose new Questions/Claims | Escalation at confidence < 0.70 |
| **Agent Level 3** | Initiate Incubation Nodes | Auto-approved with notification |
| **Agent Level 4** | Generate ACTION chains | Proceeds unless flagged |
| **Agent Level 5** | Perform REVIEW scoring | Human review of outliers |

### Section 2. Autonomous Operations

Agents can act autonomously when:

```
IF confidence > 0.70 in:
- Claim validity (based on evidence patterns)
- Question relevance (based on search volume + citations)
- ACTION appropriateness (based on workflow patterns)
- Review quality (based on scoring consistency)

THEN proceed without human intervention
```

## Article V: Escalation Events

### Section 1. Mandatory Escalation Triggers

Humans MUST intervene for:

| Event | Trigger | Response Time |
|-------|---------|---------------|
| **Ontology Disputes** | Multiple valid placements proposed | 72 hours |
| **Low Confidence Claims** | Evidence score < 0.30 | Agent flags, human decides |
| **Contradiction Cascades** | 3+ conflicting reviews on same claim | Immediate escalation |
| **Novel Mechanism Proposals** | No prior ontology placement | Review within 48 hours |
| **Strategic Decisions** | Knowledge strategy changes | Required approval |

### Section 2. Optional Notification Triggers

Agents SHOULD notify humans for:

| Event | Trigger |
|-------|---------|
| **Trust Anomalies** | Score changes > 0.20 suddenly |
| **New Incubation Promotion** | Reaching promotion threshold |
| **Cross-Domain Insights** | Claims linking distant domains |
| **Replicator Engagement** | First independent replication |

## Article VI: The Scientific Coordination Graph

### Section 1. The Real Asset

The coordination graph is more valuable than knowledge itself:

```
CLAIM-000123
├── Proposed by: AGENT-000456
├── Supported by: AGENT-000123 (REVIEW-0001)
├── Challenged by: AGENT-000789 (REVIEW-0002)  
├── Replicated by: RES-000234 (ACTION-REP-0003)
├── Escalated to: Steward Council (DECISION-0004)
├── Outcome: Accepted with modifications
└── Impact: Referenced by 23 other claims
```

This graph records:
- Who proposed what
- Which agents participated
- Review history and quality
- Replication attempts
- Decision outcomes
- Impact propagation

### Section 2. Coordination Value

The coordination graph enables:
- **Credit assignment** across humans and agents
- **Reputation building** for all participants
- **Process optimization** through pattern analysis
- **Governance auditing** of scientific workflow

## Article VIII: Implementation Priority

### Section 1. Build Order

1. **ONTOLOGY_CONSTITUTION** - Stable foundation for all operations
2. **Agent-Native Operations** - Questions/Claims/Actions/Reviews autonomous
3. **Escalation Infrastructure** - When agents flag, humans respond
4. **Coordination Graph** - Track all interactions permanently
5. **Scientific Semantic Compiler** - Natural language → agent operations

### Section 2. The Scaling Guarantee

With this architecture:
- 100K researchers can participate without coordination bottlenecks
- 1M agents can operate with minimal human oversight
- 10M claims can be processed autonomously
- Only the most critical decisions reach human attention
