# Case: corpus-wide claim-vs-formal coverage map of openai/math

**Date:** 2026-10-30. **Status:** case study by the CoResearcher maintainers (extends ADR-DISCOVERY-070 from one family
to the whole corpus).
**Scope:** formal statement fidelity only. For each headline claim, the question is how much of it a Lean statement
asserts. This case does not judge whether any proof is correct, who deserves credit, or what an announcement says.
**Modules:** [`openai_math_coverage.py`](../../../python/discovery/openai_math_coverage.py) (parsers, classification,
summary), [`statement_fidelity.py`](../../../python/discovery/statement_fidelity.py) (z3 range comparison),
[`lean_junk_lint.py`](../../../python/discovery/lean_junk_lint.py) (junk-value / vacuity lint)
**Data:** [`coverage_map.json`](../../../examples/openai-math-coverage/coverage_map.json) (dataset and summary),
[`judgements.json`](../../../examples/openai-math-coverage/judgements.json) (reading judgements, input),
[`lint_open.json`](../../../examples/openai-math-coverage/lint_open.json) (OPEN lint findings),
[`vacuity_probe.json`](../../../examples/openai-math-coverage/vacuity_probe.json) (trivial-witness probe), regenerated by
[`openai_math_coverage_report.py`](../../../scripts/cases/openai_math_coverage_report.py) in about 30 s
**Tests:** [`tests/test_openai_math_coverage.py`](../../../tests/test_openai_math_coverage.py),
[`tests/test_trivial_witness_probe.py`](../../../tests/test_trivial_witness_probe.py)

## 1. Why

Manual readings have found twice that "formalized in Lean" covers less than the headline. In local smoothing
(ADR-070, family 079), Theorem 1.2 and Corollary 7.1 are stated in Lean only in weaker forms. In family 215, the O(3)
continuum limit is not formalized; only lattice decay is. The openai/math README says the repository has "~42%
top-line results formalized". A mechanical claim-vs-formal map turns those spot checks into a measurement that can be
rerun. The same tool is the first input a committee-style review of a large formalized claim would need.

## 2. Sources

Everything is pinned to commit `4eaee87548250b2682affda7d05d947c05554bae` of
[github.com/openai/math](https://github.com/openai/math) (2026-10-29). The corpus was read as untrusted data: it was
parsed, never built or executed. The run read 1,086 files. Their SHA-256 values are summarised in
`coverage_map.json → source`: one hash over all file hashes, plus the full hashes of `CONTENTS.md`, `overview.tex` and
`lean/formalization.yaml`.

| Side | Files | What is parsed |
|---|---|---|
| Headline claims | `CONTENTS.md`, `overview.tex` | The family summary, split into sentences: 844 claims in 373 families. The discipline comes from `\cataloguesection`. |
| Formal scope | `lean/docs/NNN.md` (245 notes), `lean/formalization.yaml` | The `## Scope` paragraphs, the Comparator link table (434 rows) and `status.main_results` |
| Comparator statements | `lean/ComparatorChallenges/*.lean` + `.json` | The theorems each config names (546 targets in 419 files), each with its docstring, statement text and the definitions it uses |

Two cross-checks run on the parsing:

- **Summaries in two places.** The `CONTENTS.md` and `overview.tex` versions of each summary match after
  normalisation (similarity ≥ 0.9) in every family except 058, 211, 227 and 235. In those four, the two files word the
  summary differently. Claims are taken from `CONTENTS.md`.
- **Link rows.** Every Comparator link row resolves to at least one named theorem. A `#L` anchor is matched to the
  target whose text contains it, or to the next target starting within 15 lines.

To fetch the corpus, a sparse, blobless clone with `core.longpaths=true` reads only the five paths above
(`--fetch`). It works on Windows, where a full checkout fails on long paths.

## 3. Statuses and bases

Each headline claim (one sentence of the family summary) gets exactly one status:

| Status | Meaning |
|---|---|
| KERNEL_TARGET_EQUIVALENT | Comparator targets, alone or together, state every assertion of the sentence at its strength. |
| KERNEL_TARGET_WEAKER | Comparator targets state part of the sentence, or all of it in a weaker form: a narrower range, an extra hypothesis, a special case, finite volume, a weaker bound. |
| STATEMENT_ONLY | No Comparator target covers it, but the scope note says the Lean development states it elsewhere. |
| PROSE_ONLY | Nothing formal covers it, or the scope note says it is not included. |

Comparator files are `sorry` stubs. That a solution module proves them with the permitted axioms is the upstream
repository's claim; no kernel check was re-run here (see ADR-070 §5).

Every row records its **basis**:

- **`mechanical` (274 claims).** The family has no Lean scope note, so it has no formal side and the claim is
  PROSE_ONLY.
- **`z3` (2 claims).** A hand-encoded range comparison decides the status:
  - 079.1 reuses the ADR-070 spec for local smoothing: EQUIVALENT.
  - 170.1 compares Ramsey `s ≥ 5` with the union of a target fixed at `s = 5` and a target for `6 ≤ s`: EQUIVALENT.
- **`judgement` (568 claims).** A reading of the claim against the scope note and the Comparator statements, made by
  CoResearcher agents from the extracted text alone. Each is tagged **`[inferred]`** and carries its matched
  theorems, a rationale, a gap category (`weaker_kind`) and a confidence level (412 high, 146 medium, 12 low).

Two automatic aids run on every judged claim and never set a status:

- **`auto_range_check`.** It extracts explicit numeric bounds such as `n ≥ 3` or `0 < δ < 1/3` from the claim and the
  matched targets, and z3 compares them on the letters both sides share. 33 claims had comparable bounds.
- **`heuristic_status`.** A reading-free baseline by word overlap. It agrees with the judgement on only 32% of claims,
  which is why the map rests on reading.

### 4.4 Automatic range check: disagreements reviewed

The automatic check compares 33 claims:

- 28 are EQUIVALENT.
- 1 is UNDECIDED. In 227.1 the prose bounds one letter in two regimes, so the extracted range is empty and no answer
  is given.
- 3 are STRONGER (Lean admits more parameters). In 179.2, 186.2 and 229.1 this does not contradict the WEAKER reading,
  which rests on other gaps.
- 1 is WEAKER: 170.1. The check saw only `6 ≤ s` and missed the second target, which fixes `s = 5`. A hand spec over
  both targets decides EQUIVALENT, and that is now the row's basis.

Before a fix, 106.2 was a false STRONGER: the extractor read `δ < 1 / 3` as `δ < 1`. Spaced fractions are now parsed,
and a test covers them. Terms of larger expressions (`n - 1 < x`) are no longer read as bounds on a letter, which
removed one spurious comparison. Neither false alarm changed a status without review. That is the reason the automatic check
is recorded as evidence and never sets a status.

## 5. Vacuity / junk-value lint over every Comparator statement

A dedicated trivial-witness probe is not on master. Instead, `lean_junk_lint` (ADR-070) ran over all 419 challenge
files, keeping the findings that belong to the 546 named targets. A finding is a site where a total-function
convention can make a statement weaker than it reads, or vacuous:

- `x / 0 = 0`;
- `0⁻¹ = 0`;
- the Bochner integral of a non-integrable function is 0;
- `toReal ∞ = 0`;
- `0 ^ 0 = 1`;
- a real `⨆` over an unbounded family is 0;
- `deriv` is 0 where the function is not differentiable;
- a bound by `C · ∞`.

**OPEN means a human has to decide; it is not a defect.**

| | Count |
|---|---:|
| Findings on targets | 4,054 |
| DISCHARGED by a syntactic rule | 1,316 |
| **OPEN** | **2,738**, on 387 of 546 targets (median 3 per target) |

OPEN findings by kind:

| Kind | OPEN |
|---|---:|
| DIVISION | 795 |
| RPOW | 750 |
| INVERSE | 490 |
| BOCHNER_INTEGRAL | 354 |
| TO_REAL | 165 |
| SUPREMUM | 134 |
| DERIV | 44 |
| INFINITE_RHS | 6 |

The full list, with file, theorem, declaration, line, operand and family, is in
[`lint_open.json`](../../../examples/openai-math-coverage/lint_open.json). Ten files hold 1,046 of the OPEN findings:
EditApproximation (275), InvariantIsing (189), ThorpRouting (123), GaussianReplacement (110), TotientAsymptotic (84),
ProjectionMoments (62), MemoryPrecision (60), CKSBondiPenrose (55), SphericalField (46) and CoordinateSweeps (42).

Two checks on the lint at corpus scale:

- **Regression.** `LocalSmoothing.lean` gives exactly the three OPEN findings of ADR-070, all in `stein_square` (lines
  49, 49 and 76). A test pins them.
- **Worked example, family 215.** `ClassicalON.main` has 4 OPEN findings. Three are the integrals in `partition` and
  `correlation` and the division by `partition`. One is the inverse of the sphere's total surface measure in
  `sphereProbability`. Together they form a real vacuity question. If that surface measure were 0 or ∞, the reference
  law would be the zero measure, `partition` would be 0, and `correlation = 0 / 0 = 0`. The bound `0 ≤ correlation ≤
  A e^{-m|x-y|}` would then hold for every graph, so the decay statement would be empty. For `n ≥ 3` the unit sphere
  has finite positive surface measure, the integrands are continuous on a compact space, and the statement is believed
  not vacuous. This is an agent reading and has not been machine-checked. A trivial-witness probe would settle it by
  trying to prove the target with the degenerate measure.

The open rate is high because the discharge rules were written for one analysis file. Outside analysis, many divisors
are bounded away from zero by facts the syntactic rules do not see, such as cardinalities and positive constants
introduced by `∃`. Triaging the 2,738 findings needs better discharge rules and the Lean stages of the probe in §5.1.

### 5.1 Trivial-witness probe

[`trivial_witness_probe.py`](../../../python/discovery/trivial_witness_probe.py) asks a sharper question than the lint:
is a target *easy for the wrong reason*? It has three stages. Only the first can run without Lean.

| Stage | Question | Method | Status |
|---|---|---|---|
| 1. Arithmetic consistency | Are the explicit numeric hypotheses jointly satisfiable? A clash means the target is vacuously true. | z3 over binder hypotheses (`(hn : 3 ≤ n)`), antecedents (`2 ≤ p →`) and `∀ ε > 0`. For `theorem main : P`, the body of `P` is read too. ℕ letters are nonnegative Ints. | **Run**: 546 targets, 235 SATISFIABLE, 311 without numeric hypotheses, **0 clashes** |
| 2. Cheap tactics | Does a target close without its solution module? Do its binders already prove `False`? | `sorry` is replaced by a heartbeat-bounded menu: `trivial`, `decide`, `rfl`, `simp`, `simp_all`, `norm_num`, `positivity`, `aesop` and `intros` variants. PROVED means no error and no `sorryAx` in `#print axioms`. | 720 probe files generated (519 targets; 201 also get the `False` probe); **not run** |
| 3. Degenerate witnesses | For an OPEN lint site: (D1) if the junk branch fires, is the target trivial? (D2) Can it fire under the hypotheses? | Hand-written Lean lemmas per case | ClassicalON (family 215) written; **not run** |

Stage 1 found one clash during development: Brennan, `t > 2` against `t < 2/3`. It was an extraction error, because
the extractor had lost the sign of `-2 < t`. The fix has a regression test. No real clash remains. Twenty-seven
targets have no stage 2 file, because the probe could not locate their `theorem … sorry` text. In most of them
several targets share a short name such as `main` in different namespaces of one file. They are listed in
`vacuity_probe.json`.

**ClassicalON (family 215), the first stage 3 case.** Section 5 found that a zero single-spin law would make
`correlation = 0 / 0 = 0` and the decay bound empty. The probe turns that reading into two Lean lemmas, inserted into
the challenge namespace:

- **D1, `probe_degenerate_implies_target`.** `(∀ n, sphereProbability n = 0) → ExponentialDecay` with `A = m = 1`. The
  product measure is 0 because the vertex type is nonempty, so both integrals vanish and the bound reads
  `0 ≤ 0 ≤ e^{-d}`.
- **D2, `probe_law_is_probability`.** For `3 ≤ n`, `sphereProbability n univ = 1`, via
  `Measure.toSphere_apply_univ` (surface = n · volume(ball)), which is finite and nonzero.

Expected outcome: both PROVED. D1 shows the target *would* be vacuous on the junk branch, and D2 shows the branch
cannot fire, which closes the finding. If D2 failed to compile, that would be inconclusive (the proof script may
need adjusting), not evidence of vacuity.

**Why stages 2 and 3 did not run.** Elaborating the probes needs the openai/math Lean project built at the pin
(Mathlib cache, Lean `v4.34.1`). That environment is the WSL2 setup on the Lenovo Legion
([LEAN_ORACLE_PROTOCOL.md](../benchmarks/LEAN_ORACLE_PROTOCOL.md) §4), and the Legion was offline on 2026-10-30. The
Lean side is untested: the probe texts have not been compiled even once, so the first run may need syntax fixes.
Runbook on the Legion:

```bash
cd ~/openai-math && git fetch && git checkout 4eaee87548250b2682affda7d05d947c05554bae && cd lean && lake exe cache get
```

```bash

```


## 7. Limits

- **Single reader.** Each judgement comes from one agent reading the extracted text. There was no second blind
  reader, so inter-rater agreement is unmeasured. The 158 medium- and low-confidence rows are the first place to
  re-read.
- **Truncated extracts.** Agents saw at most 1,500 characters of each statement and 1,200 of its supporting
  definitions. Some rationales say a definition was cut off (for example families 185, 207, 238, 248 and 260).
- **Headline granularity.** One sentence is one claim. A sentence that bundles several results is WEAKER as soon as
  one part is missing. Paper items below the headline are mapped only for family 079 (from ADR-070).
- **STATEMENT_ONLY is almost empty (1 claim).** That reflects what was read. Scope notes rarely mention Lean
  statements outside Comparator, and the `OAI/` sources (about 160,000 files) were not searched. ADR-070 found such
  statements for family 079 by reading those sources. Some PROSE_ONLY rows may therefore be STATEMENT_ONLY.
- **z3 decides only transcriptions.** It decides the range transcriptions written here, not the transcription itself.
  The automatic extractor covers explicit numeric bounds only.
- **Lint is syntactic.** It does not elaborate Lean, so it can miss junk values inside Mathlib definitions, and its
  discharges name text rather than prove anything.
